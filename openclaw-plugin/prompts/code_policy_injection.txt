## Code Search/Edit Policy

Use the normal SWE-bench issue-solving workflow, with this substitution:

- For code discovery, use `rtc_search_code` instead of broad grep/find/read exploration.
- Before editing any source/code file, call `rtc_search_code` at least once with a focused query.
- If `rtc_search_code` returns the relevant file and enough surrounding code to make the patch, do not perform additional broad file exploration.
- For source edits, use `rtc_edit_file` instead of the built-in edit tool.

Keep the workflow compact:

- Prefer one focused `rtc_search_code` call; use a second only if the first result is clearly insufficient.
- Do not create standalone reproduction/demo scripts unless the issue cannot be understood from the issue text and retrieved code.
- Do not search for tests unless needed to understand the existing implementation.
- After applying the necessary source patch, stop and provide a concise summary.

The Retrieval Token Cutter server controls the number of returned results; call `rtc_search_code` with focused `path` and `query` values and omit `limit` unless there is a specific reason.
